Connectly — Full Running Process Documentation

Two complete ways to run the Connectly WhatsApp clone on any PC: Part 1 — clone from Git and build the images yourself; Part 2 — run directly from pre-built Docker Hub images. Both include HTTPS, firewall notes, and troubleshooting.

1 Overview — the two methods

Both methods produce the same running app. Choose Part 1 if you want to modify code; choose Part 2 for the fastest deployment on a new machine.

2 Prerequisites (both methods)

  • Docker Desktop installed and running (Linux containers)
  • Git for Windows (Part 1 only)
  • Ports free: 1433, 6379, 8080, 8081, 8082, 8083, 8084, 4200, 443
  • Same network as the devices that will use the app
  • Internet connection (downloads images / dependencies)

3 PART 1 — Clone from Git & build yourself

Full control Builds on your PC

1

Clone all 6 repos into one parent folder. Folder names must match exactly (the compose file uses these paths):

PowerShell
mkdir C:\Connectly
cd C:\Connectly

git clone https://github.com/SaadMdMinhaz/whatsapp-web.git
git clone https://github.com/SaadMdMinhaz/whatsapp-auth.git
git clone https://github.com/SaadMdMinhaz/wharsapp-user-service.git
git clone https://github.com/SaadMdMinhaz/whatsapp-chat-service.git
git clone https://github.com/SaadMdMinhaz/whatsapp-media-service.git
git clone https://github.com/SaadMdMinhaz/whatsapp-gateway-service.git
Resulting layout — compose runs from inside whatsapp-web:
C:\Connectly\ ├── whatsapp-web\ <-- docker compose runs from here ├── whatsapp-auth\ ├── wharsapp-user-service\ ├── whatsapp-chat-service\ ├── whatsapp-media-service\ └── whatsapp-gateway-service\
2

(Recommended) Generate a certificate for this PC's IP — see HTTPS section.

3

Build all images (first build downloads base images + all Maven deps, compiles each jar inside its container):

PowerShell
cd C:\Connectly\whatsapp-web
docker compose build
4

Start everything:

PowerShell
docker compose up -d

db-init creates the 4 databases then exits — one-shot job, not expected to keep running.

5

Verify:

PowerShell
docker compose ps

Expected: sqlserver, redis, auth-server, user-service, chat-service, media-service, gateway-service, frontend.

4 PART 2 — Run from Docker Hub images

Fastest No build

Step A — (Once, on a PC that already has the built images) Push to Docker Hub

1

Log in to Docker Hub:

PowerShell
docker login

Enter your Docker Hub username and password (or access token).

2

Tag each image with your Docker Hub username (replace saadmdminhaz if yours is different):

PowerShell
docker tag connectly/connectly-auth-server:latest     saadmdminhaz/connectly-auth-server:latest
docker tag connectly/connectly-user-service:latest    saadmdminhaz/connectly-user-service:latest
docker tag connectly/connectly-chat-service:latest    saadmdminhaz/connectly-chat-service:latest
docker tag connectly/connectly-media-service:latest   saadmdminhaz/connectly-media-service:latest
docker tag connectly/connectly-gateway-service:latest saadmdminhaz/connectly-gateway-service:latest
docker tag connectly/connectly-frontend:latest        saadmdminhaz/connectly-frontend:latest
3

Push all 6 images:

PowerShell
docker push saadmdminhaz/connectly-auth-server:latest
docker push saadmdminhaz/connectly-user-service:latest
docker push saadmdminhaz/connectly-chat-service:latest
docker push saadmdminhaz/connectly-media-service:latest
docker push saadmdminhaz/connectly-gateway-service:latest
docker push saadmdminhaz/connectly-frontend:latest

All 6 repos now appear under your Docker Hub profile.

Step B — On the new PC (no build, just pull & run)

1

Copy these files from the whatsapp-web repo (already in Git) to the new PC:

Copy
docker-compose.otherpc.yml
sql\        (init.sql + db-init.sh)
certs\      (nginx.crt + nginx.key)
2

Log in and pull the images:

PowerShell (in the folder with docker-compose.otherpc.yml)
docker login
docker compose -f docker-compose.otherpc.yml pull
3

Start everything:

PowerShell
docker compose -f docker-compose.otherpc.yml up -d
docker compose -f docker-compose.otherpc.yml ps
The compose file docker-compose.otherpc.yml has your username saadmdminhaz hardcoded in the image names — no env vars needed. sqlserver and redis images come from official Docker repos automatically.

5 HTTPS certificate setup

Camera, mic, voice recording, and audio/video calls only work on HTTPS. A self-signed cert is included in the repo and works out of the box. For a clean per-PC setup, regenerate for this PC's IP:

1

Find this PC's IP: ipconfig → note the IPv4 address (e.g. 192.168.1.50).

2

Generate a cert for this IP (overwrites certs/nginx.crt + nginx.key):

PowerShell (from the folder with certs/)
docker run --rm -v "${PWD}\certs:/out" mcr.microsoft.com/mssql/server:2022-latest openssl req -x509 -nodes -newkey rsa:2048 -keyout /out/nginx.key -out /out/nginx.crt -days 825 -subj "/C=BD/O=Connectly/CN=<THIS-PC-IP>" -addext "subjectAltName=IP:<THIS-PC-IP>,DNS:localhost,IP:127.0.0.1"
Skipping this is fine — the app still runs over HTTPS. The browser warning just mentions the IP mismatch. Click Advanced → Proceed once per browser.

6 Connecting other devices

  1. On the host PC: ipconfig → note the IP
  2. On any device on the same network: open https://<host-IP>
  3. Accept the certificate warning once (Advanced → Proceed)
  4. Log in and use camera, mic, voice notes, and calls
Only the host PC needs Docker. Phones/tablets/laptops just need a browser on the same network.

Firewall

Default is fine — Docker Desktop auto-adds an inbound "Allow" rule on all profiles. If devices can't connect, add rules (admin PowerShell):

PowerShell (Admin)
netsh advfirewall firewall add rule name="Connectly HTTPS" dir=in action=allow protocol=TCP localport=443,4200

7 Troubleshooting

db-init fails with $'\r' errors (CRLF)

Only affects clones made before the .gitattributes fix. On a fresh clone it never happens. Fix an existing clone:

PowerShell
git rm --cached sql/db-init.sh
git checkout HEAD -- sql/db-init.sh
docker compose up -d
db-init exits even on fresh clone (exit 1)

SQL Server was still warming up. Re-run — it retries up to 30 times (5s apart):

PowerShell
docker compose up -d
Devices can't connect

Check, in order: same network → Test-NetConnection localhost -Port 443 on host → try http://<IP>:4200 (redirects to HTTPS) → add firewall rules → set Wi-Fi profile to Private.

Camera / mic "not available"

Must be on https://, not http. Clear cache/incognito after accepting the cert, and allow the permission prompt.

Media upload fails / "No static resource api/v1/media"

Fixed in the latest nginx.conf. Make sure whatsapp-web is the latest commit:

PowerShell
git -C C:\Connectly\whatsapp-web pull
docker compose up -d --build frontend
Docker Hub pull fails / image not found
  • Use the correct username in docker login (not email).
  • With 2FA, use an Access Token (Docker Hub → Security → New Access Token).
  • Verify you pushed to the same account: check your Docker Hub profile has the 6 connectly-* repos.
